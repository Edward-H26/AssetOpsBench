# v5定向debug：独立GPU

用户授权与v4并行申请另一张GPU，优先定位和修复问题。本轮是3场景×2配置的6回合小规模测试，不是全量实验。

GPU作业14029696已提交，调度状态与结果见SUMMARY.md和sync.json；当前尚无真实模型成绩。v4的14027301和冻结代码保持不变，两轮使用各自服务地址与密钥，不向同一模型服务并行发请求。

## 先测什么

| 场景 | 配置 | 要检查的问题 |
|---|---|---|
| Scenario1，seed0 | v5带/不带诊断MCP | 输出是否仍传错参数；诊断、维修、核验后能否主动结束 |
| Scenario2，seed0 | v5带/不带诊断MCP | 有泵和冷却器故障时，能否停止重复空读并完成多部件维修 |
| Scenario6，seed1 | v5带/不带诊断MCP | 真实思考计时与劣化发生后，是否重新取证并调整维修 |

PE的未修改基线继续由v4整轮提供；不同GPU的时延结果不能混成正式对照，本轮首先定位自有agent的执行问题。

## 如何查看和迭代

代码和配置冻结在source/、configs/，SHA256与6任务清单在manifest.json。每个回合的episodes/debug_trace.jsonl逐轮写出模型请求、原始回复、计划解析/检查结果、执行反馈；不必等episode结束才知道no_call的原因。

发现问题时先引用具体原文与拒绝原因，区分程序、接口、提示、决策及环境按规则失败；当前版本保留，再以新版本修复。不自动转换模型错误参数、不替模型给答案、不通过放宽评分制造成功。

本次GPU最多4小时，6项记录完成后自动打包归档并停服释放，不常驻。本地只读同步程序每120秒同步进度，完整归档完成后校验SHA256并下载。此前v4整轮完成后自动停GPU的安排不变。
