# v004 分析

## 设计

修复无profile/无wait开局崩溃；保留并逐步原生检查模型未执行步骤，观测/时钟变化或surprise后重规划；短提示展示可读周期与最近返回数，拒绝已知空静态窗口。环境与verifier不变。

## 实测证据

本地与集群11项协议检查通过。CPU作业14020029已在集群启动，复用GPU服务14011256；固定Scenario2007、seed0、Granite3.3-8B BF16/128K，先MCP后无MCP。尚无最终成绩，不能推断收益。

## 与v003的具体差异

- profile尚未读取时不访问forward_read，新增无profile、无wait的四种组合检查。
- 每轮仍只执行模型提议的一个动作，但其余动作保留。只在没有新观测、没有时间变化、没有surprise时继续检查并执行模型的下一步；否则要求模型重新规划。没有替模型生成诊断或选择维修部件。
- 每个待执行动作继续通过原check_plan，因此重复诊断、重复工单和过早finish仍被拒绝。
- prompt展示各传感器组未读的历史周期数，以及最近一次history/read_sensors的返回行数。已知没有未读历史、读取不推进时间且无后台时间演化时，debug控制器拒绝该空读意图，并解释可选择等待或利用已有证据。无MCP的前向读取仍允许。
- 调查阶段改用短协议提示，减少旧多步目标与实际执行阶段的冲突。MCP排序、干预预测和维修后核验仍作为原来的建议与检查，不改真相或verifier。

## 比较限制

空读意图检查属于debug控制器新增约束，所以本版是新变体，不是原agent未经修改的分数。±MCP两组应用同样修改，但原工具可用性仍不同。本版要先验证执行链条，不能据单场景的一次成败推断普遍收益。
