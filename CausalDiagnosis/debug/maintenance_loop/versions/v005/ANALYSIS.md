# v005设计与验证

## 本版设计

v4的执行逻辑逐字复制，不改其检查条件。新的_generate包装只在调查规划阶段替换提示，保留开局阶段。提示使用实际设备profile中的组名和组件，不写死液压机故障，也不提供隐藏状态。

当前没有未读数据且v4本来就会拒绝读取时，提示中不再把read列为当前可选下一步；前向读取、思考计时产生数据时仍列出read。没有开放的wait不会被虚构为可用工具。执行时仍由原逻辑判断模型实际提出的动作。

维修后给出已经收到的公开核验结果，并提醒根据全机恢复证据决定是否结束。finish仍由模型提出；wait仍可被选择，没有新增自动结束策略。

逐轮日志保留实际发给模型的提示、原始回复、原检查错误及执行后的公开状态。每一轮未执行的原因可直接从日志读出。失败回复不被改写成合法动作。

## 离线验证

`source/test_protocol.py`的离线检查覆盖：无profile/无wait开局；实际组名与必填字段；原parser仍拒绝通道数组；已读完历史时的提示；前向/思考计时读数仍可选；无时钟时不提示wait；公开核验与finish建议不自动选择动作；逐条日志落盘；实际控制器解析失败保持拒绝且留下原文；正常调查提示可渲染并保留原拒绝原因。

这些检查不调用真实模型，不是成功率或MCP收益。

## 后续评估边界

v005的定向运行（`rounds/v5_targeted`）与v4整轮分开运行。比较分别看格式失败、实际动作、诊断、修复、核验、主动结束、成本和耗时；不同GPU时延必须保留硬件差异，不能混为正式显著性结论。

三配置对照仍为PE+MCP、本目录的agent+MCP、本目录的agent无MCP。现有无MCP组工具较少的限制本版没有偷偷改变；因果建议的独立收益仍需后续同工具能力的消融。
