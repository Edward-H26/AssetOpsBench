# v001 分析

这是已完成历史运行的归档，未重新生成结果。基线与本版固定Scenario2007、seed0，同一Granite8B模型。

## 修改

仅修改prompt：开局先读profile，再查询故障模式、维修历史和surface需要的信息；明确计划kind与MCP函数名不同，branch可为null，组件键与证据ID取真实返回值。

## 结果与证据

- MCP组：8次环境工具调用、1次诊断MCP调用，0次实际传感器读取。整计划因过早finish或缺少维修后验证被拒绝，最终max_steps，pass=False。
- 无MCP组：10次环境工具调用。trajectory第8步读取5行，第9步提交正确全组件诊断，第10步创建泵工单。工单在cycle0创建，预计cycle5关闭；后续模型输入的Work orders表确实显示open。
- 无MCP后续48轮重复诊断/重复给泵下单，被原检查器拒绝；时间停在cycle0，未恢复，pass=False。

具体输入输出、计划与评分见 [本次运行](runs/imported/README.md)。不能将“无MCP诊断正确”写成“无MCP已成功维修”。

## 解释

开局协议改善有效；之后仍有整段计划的可执行性和进度处理问题。MCP组没有拿到实际传感器数据，不能据此判断诊断工具本身质量。
